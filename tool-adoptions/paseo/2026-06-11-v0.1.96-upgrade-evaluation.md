第一阶段合并官方 `v0.1.93` 时的主要冲突文件：

第二阶段继续合并官方 `v0.1.96` 时无 Git 冲突，Git 自动生成 merge commit（合并提交）`adcbe34e`。

保留策略：

- 保留 `/archive-session` 作为显式归档入口；不把 close tab（关闭标签页）或 `archive_agent_request` 恢复为隐式归档。
- 保留 `archive_agent_request` 禁用语义，继续提示使用 `/archive-session`。
- 保留 `close_items_request` 对 agent ids（智能体 ID）的 no-op（无操作）语义，只处理 terminal（终端）关闭。
- 保留 native unarchive（原生取消归档）和 native archived sync（原生归档状态同步），并迁移到官方 `listImportableSessions` 结构。
- 保留 Codex app-server provider（Codex 应用服务器提供方）的 compact timeout（压缩超时）兼容、archived thread（已归档线程）读取和 cwd（当前工作目录）过滤。
- 保留 Claude `xhigh -> max` 环境配置兼容。
- 保留 internal Paseo MCP（内部模型上下文协议）只注入 provider launch config（提供方启动配置），不写入用户可见的 stored config（已存储配置）。

第一阶段还修复了合并过程中暴露的 live agent（运行中智能体）metadata（元数据）更新问题：`updateAgentMetadata` 必须操作 manager 内部真实 agent，而不是 `getAgent()` 返回的拷贝；否则 MCP `update_agent` 可持久化 title（标题），但内存 labels（标签）不会更新。

## 隔离边界

本轮只在 `.worktrees/paseo-upgrade` 内构建和运行测试。测试使用 Vitest（测试框架）和构建产物，不会连接或重启真实用户正在使用的 Paseo daemon。

可以启动隔离测试 daemon，但必须显式设置独立 `PASEO_HOME`（Paseo 本地状态目录）和独立监听地址，且不得覆盖全局 `paseo` link。例如只允许后续使用临时目录与非真实端口做人工冒烟。

## 剩余风险

## 2026-06-14 最新版复核

当前官方最新稳定版已到 `0.1.96` / npm `@getpaseo/cli@0.1.96`。本地已 fetch（拉取）上游 tag（标签）`v0.1.94`、`v0.1.95`、`v0.1.96`，并已把升级分支从 `v0.1.93` 前移到 `v0.1.96`。

上游 `0.1.94` 到 `0.1.96` 的相关变更：

- `0.1.94`：增加 PR panel（Pull Request 面板）附件、国际化、terminal profiles（终端配置）、Antigravity 编辑器入口；改进 Claude skills autocomplete（Claude 技能自动补全）、file preview tab（文件预览标签）路径复制、workspace tabs（工作区标签）保留策略；修复 imported sessions（导入会话）空白/错 workspace、worktree terminal（工作树终端）出现在父 workspace 等问题。
- `0.1.95`：增加桌面端任意文件附件；改进 git push 按钮优先级、SVG 附件落盘、workspace 切换流畅度；修复 GitHub 数据过期、缺失项目路径错误提示、Android sidebar（侧边栏）等问题。
- `0.1.96`：只修 Android sidebar 打开 chat 后卡住；官方 changelog（变更日志）明确说明 desktop users（桌面用户）不需要升级。

对当前三个阻塞问题的判断：

1. 点击打开已归档会话失败：`v0.1.96` 的 `packages/server/src/server/agent/agent-loading.ts` 仍然会在存在 persistence handle（持久化句柄）时直接调用 `resumeAgentFromPersistence`，没有针对 stored agent（已存储智能体）的 `archivedAt` 分支；因此不能指望 `0.1.96` 自动解决 Codex archived thread（已归档线程）被普通 resume（恢复）拒绝的问题。
2. `/archive-session` 后 UI（用户界面）不即时变化：`0.1.94` 到 `0.1.96` 的归档 UI 相关差异主要是 i18n（国际化）和文案，没有看到针对本地 `/archive-session` 命令成功后刷新 session store（会话状态存储）或 workspace tabs store（工作区标签状态存储）的明确修复。
3. 刷新后所有未归档会话进入 tab 栏：`0.1.94` 增加了 workspace deck retention（工作区页面保留）策略，并限制保留最近 workspace screen（工作区屏幕），但 `packages/app/src/workspace-tabs/agent-visibility.ts` 和 `workspace-layout-actions.ts` 的 auto-open（自动打开）核心规则没有实质变化；这可能改善跨 workspace 渲染压力，但不是对“当前 workspace 内所有未归档 agent 自动进 tab 栏”的明确修复。

结论：升级目标已前移到 `0.1.96`，可以保留新版 workspace tabs 性能、file preview、import sessions 和桌面附件能力；但它不能替代本地修复。当前三个阻塞问题仍应按本地修复计划统一处理。
