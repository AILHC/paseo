# Paseo v0.1.96 定制升级 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在已有 Paseo worktree（独立工作树）中，将当前定制版从 `v0.1.85-9-g2048ca8f` 升级到官方稳定版 `v0.1.96`，保留本地定制语义，完成验证后再决定是否更新父仓库的 `vendor/paseo` gitlink（子模块指针）。

**Architecture:** 使用已有子模块 worktree `.worktrees/paseo-upgrade` 作为升级隔离区。先把官方 `v0.1.96` 合入升级分支，再按文件逐项恢复本地定制逻辑。升级期间不修改主 worktree 的 `vendor/paseo` checkout（检出状态），也不更新父仓库子模块指针。

**Tech Stack:** Git（版本控制）、Paseo monorepo（单体仓库）、Node.js（JavaScript 运行时）、npm（包管理器）、TypeScript（类型系统）、Vitest（测试框架）、Codex app-server provider（Codex 应用服务器提供方）。

## 上游 v0.1.86 到 v0.1.96 影响面

必须保留官方 `v0.1.96` 的功能更新，尤其是这些容易与定制逻辑交叉的区域：

- agent（智能体）列表、分组、归档、会话导入、workspace（工作区）打开逻辑。
- multiple desktop windows（多桌面窗口）、workspace tabs（工作区标签页）、file preview（文件预览）、外部浏览器打开链接。
- provider catalog（提供方目录）、provider refresh（提供方刷新）、OMP provider（OMP 提供方）、OpenCode summaries（OpenCode 摘要）。
- configurable worktree root（可配置 worktree 根目录）、自动归档干净的 PR workspaces。
- Codex compact（压缩上下文）、goals（目标）、auto review（自动评审）相关上游改动。
- desktop skills（桌面技能）、skills autocomplete（技能自动补全）相关命令能力。

本地定制不能用旧版本文件整体覆盖官方 `v0.1.96` 文件；只能把必要逻辑移植到新结构中。

## 定制逻辑合并判定

### 1. `/archive-session` 显式归档入口

结论：保留。

本地语义：

- 只有用户显式发送 `/archive-session` 时，才归档 agent session（智能体会话）。
- `listCommandsForAgent(agentId)` 需要把 `/archive-session` 命令加入当前 agent 的命令列表。
- `sendPromptToAgent` 识别 `/archive-session` 后执行归档，并返回 out-of-band（带外）结果，避免把命令作为普通 prompt（提示词）发送给 provider（提供方）。

涉及文件：

```text
packages/server/src/server/agent/agent-manager.ts
packages/server/src/server/agent/agent-prompt.ts
packages/server/src/server/session.ts
packages/server/src/server/snapshot-mutation-ownership.test.ts
packages/server/src/server/agent/agent-manager.test.ts
packages/server/src/server/session.workspaces.test.ts
```

合并策略：

- 保留官方 `v0.1.96` 的 `archiveAgent`、`archiveSnapshot`、级联归档和事件处理结构。
- 在新结构上添加 `archiveSession` / `archiveSessionSnapshot` / `listCommandsForAgent` 这类显式入口。
- 不把 `/archive-session` 实现为前端按钮或 close tab（关闭标签页）的隐式行为。

### 2. 禁止关闭标签页隐式归档 agent

结论：保留，并覆盖官方默认行为。

官方 `v0.1.96` 仍会在以下入口归档 agent：

- `archive_agent_request`
- `close_items_request` 中的 `agentIds`

本地语义：

- `archive_agent_request` 禁用，并提示使用 `/archive-session`。
- `close_items_request` 对 `agentIds` 执行 no-op（无操作），只关闭 terminal（终端）等非 agent 项。

涉及文件：

```text
packages/server/src/server/session.ts
packages/server/src/server/session.workspaces.test.ts
```

合并策略：

- 保留官方 `close_items_request` 对 terminal 的处理。
- 删除或绕过官方对 `agentIds` 的隐式归档循环。
- 测试必须覆盖 close tab 后 agent 没有被标记 archived（已归档）。

### 3. Codex 原生 unarchive（取消归档）

结论：保留。

本地语义：

- 取消归档 Paseo snapshot（快照）时，也调用 Codex app-server 的 `thread/unarchive`。
- 如果 Codex 返回“已经不是归档状态”这类幂等错误，不应失败。

涉及文件：

```text
packages/server/src/server/agent/agent-manager.ts
packages/server/src/server/agent/agent-sdk-types.ts
packages/server/src/server/agent/provider-registry.ts
packages/server/src/server/agent/providers/codex-app-server-agent.ts
packages/server/src/server/agent/providers/codex-app-server-agent.test.ts
packages/server/src/server/agent/agent-manager.test.ts
```

合并策略：

- 在 `AgentClient`（智能体客户端）接口中保留 `unarchiveNativeSession?(handle)`。
- 在 provider registry（提供方注册表）包装层转发 `unarchiveNativeSession`。
- 在 Codex provider（Codex 提供方）中实现 `thread/unarchive`。
- 在 `AgentManager.unarchiveSession` 中先尝试原生取消归档，再更新 Paseo 本地 snapshot。
- 保留幂等错误兼容逻辑。

### 4. Codex 原生归档状态后台同步

结论：保留，但必须适配 `v0.1.96` 的最新 agent 列表和 provider 结构。

本地语义：

- Codex 原生侧已经归档的 thread（线程）应同步回 Paseo 本地 registry（注册表）。
- 同步只处理已持久化、非 live（非运行中）、当前未标记 archived 的 agent。
- 同步不能阻塞 `fetch_agents_request` 或 `fetch_agent_history_request`。
- 同步必须有 in-flight（进行中）保护和 cooldown（冷却时间），当前本地值是 30 秒。
- 后台同步有 2 秒 timeout（超时），失败只记录 warn（警告），不影响列表返回。

涉及文件：

```text
packages/server/src/server/session.ts
packages/server/src/server/agent/agent-manager.ts
packages/server/src/server/agent/agent-sdk-types.ts
packages/server/src/server/agent/providers/codex-app-server-agent.ts
packages/server/src/server/agent/providers/codex-app-server-agent.test.ts
packages/server/src/server/session.workspaces.test.ts
```

合并策略：

- 在 `PersistedAgentDescriptor`（持久化智能体描述）中保留 `archivedAt?: Date | null`。
- Codex provider 的 `listPersistedAgents` 同时读取 active（活跃）和 archived（已归档）列表。
- 通过 `thread/list { archived: true }` 读取 Codex 原生归档 thread。
- 仍按 cwd（当前工作目录）匹配过滤，避免跨 workspace 错标。
- 在 `Session.listFetchAgentsEntries` 附近触发后台同步，但不 await（等待）同步完成。
- 不用该逻辑替代官方 `v0.1.96` 的 agent 列表分页、订阅或排序逻辑。

### 5. Codex compact timeout 兼容

结论：保留兼容补丁，但不覆盖官方 compact 主流程。

- 该场景下继续等待后续 compacted notification（压缩完成通知），不要立即把 compact 流程判失败。

涉及文件：

```text

packages/server/src/server/agent/providers/codex-app-server-agent.test.ts
```

- 只把 `isIgnorableCompactStartError` 和对应 catch（捕获）逻辑移植到新实现。
- 测试必须证明非该错误仍然失败。

本地语义：

- UI / Paseo 内部允许 `xhigh` thinking effort（思考强度）。
- Claude SDK（软件开发工具包）侧要映射为 `max`，避免传入 SDK 不接受的值。

官方 `v0.1.96` 已包含部分 provider wrapper（提供方包装器）能力，例如 `listCommands`、`listFeatures`、`archiveNativeSession`。本地只需要确认并补齐：

涉及文件：
